# ADC 采样修正及原作者实现核对

后续已实施按新有效组更新PI，当前板上固件与结果见[新采样驱动PI报告](../foc_fresh_sample/README.md)。本目录保留ADC修正阶段的历史记录。

本轮实际修改、编译并烧录了开发机 `develop` 的 `/home/bgzerol/embedded_project/foc_balance_car/esp32/balance_car`。功率引脚始终无PWM输出，未修改或编译原作者工程。

## 原作者怎样采电流

原作者应用层在 `SuperCar.cpp:44` 创建两个 `LowsideCurrentSense(0.005f, 50.0f, ...)`，分别使用 GPIO2/3 和 GPIO4/5；`linkDriver()` 后调用 `init()`，由 SimpleFOC 完成 ADC 与 PWM 同步。主循环 `running()` 依次调用两台电机的 `loopFOC()`，没有自行编写 ADC 中断、DMA 或 RTOS 电流环任务。

本地 `platformio.ini` 声明 `askuric/Simple FOC@^2.3.3`，当前 `.pio/libdeps/.../Simple FOC/library.properties` 实际是 **2.4.0**。因此以下是当前本地依赖的源码事实，不能据此断言作者当年的实际固件使用了同一版本。

当前依赖的 `src/current_sense/hardware_specific/esp32/esp32_mcpwm_mcu.cpp`：

- `_driverSyncLowSide()` 优先寻找空闲比较器，安装比较事件回调，找不到时回退为定时器 `on_full`，即 TEP 回调。
- `_mcpwmComparatorADCCallback()` 和 `_mcpwmTriggerADCCallback()` 每次都只读取一个通道，`buffer_index` 在当前电机 A/B 间轮换。
- `_readADCVoltageLowSide()` 只从 `adc_buffer` 取最近值，供 `loopFOC()` 使用。
- ESP32-S3 的 `adcRead()` 直接写 SAR ADC 启动寄存器并轮询完成位，未使用 DMA；其 ADC 读取函数有自己的临界区。
- 默认预触发宏为 `SIMPLEFOC_CS_PRETRIGGER_US=5`，但不能将这个宏当作已测得的准确提前时间。源码公式为 `peak_ticks*(0.75-f_pwm*pretrigger_us/1e6/2)`，存在 TODO，且注释说下数触发而代码实际筛选上数 `MCPWM_TIMER_DIRECTION_UP`。以20kHz及这段实现计算，比较点在 TEP 前约7.5μs，不应照抄成“准确提前5μs”。
- 原作者没有显式指定 PWM 频率，当前依赖的默认值为25kHz；本工程实验按用户要求固定20kHz。

所以，原作者/库采取的是“同步触发→每次采一相→缓存给自由循环FOC读取”。它减少单次ISR时间，代价是A/B来自不同PWM周期，且当前缓存接口不提供各相年龄和完整AB组序号。没有证据证明原作者已在真实硬件上验证所有占空比下的采样窗口。

另一个边界：原作者 `ButtonAndBattery.cpp:51` 还通过普通 `analogRead(BAT_ADC_PIN)` 在任务中测母线。这不属于低侧同步采样路径，不能直接照搬为本工程的ADC1并发管理方式。

原始实现依据：[SimpleFOC v2.4.0 ESP32低侧采样源码](https://github.com/simplefoc/Arduino-FOC/blob/v2.4.0/src/current_sense/hardware_specific/esp32/esp32_mcpwm_mcu.cpp)。本轮对照同时直接读取了本地依赖文件。

## 本轮已实施的改动

保留每个PWM周期采同一电机AB，交替M1/M2，每相目标10kHz。

1. 将ADC ISR与显示/FOC统计共用的大锁拆开。ISR不再等待跨核显示锁。
2. 使用同组备用MCPWM定时器，由主定时器TEZ硬件同步，每次重载为向上计数120tick，使它的TEP位于主PWM的TEP前12μs。主PWM依然20kHz，不依靠软件延时，也不占用两电机六个占空比比较器。
3. MCPWM定时器在core0创建，ADC中断因此位于core0；I2C、sensor处理和自由循环FOC仍位于core1。IRQ保持等级3。
4. ADC向FOC发布原子字段加序号锁快照；ISR只写、不等待读者。FOC最多尝试三次，无法取得一致快照时沿用上次完整快照，不读到一半AB。
5. 跨核数据年龄使用共同的 `esp_timer_get_time()` 时间基准，避免直接相减两个核各自的CCOUNT。年龄统计分辨率为1μs。
6. 高频ADC在sensor同步初始化完成后才启动。
7. 转换失败、零码/满量程或估计AB完成已跨越下一主PWM TEZ时，整组拒绝，保留上次完整AB与时间戳，不增加有效组序号。完成时间判断增加一个0.1μs计数tick的余量。

FOC任务仍为core1优先级0、自由循环、`taskYIELD()`，沿用上一轮Idle hook协作方式；本次没有改成固定频率FOC。

## 一项测量修正

之前将SDK的计数补偿直接用于“峰值后的相位”计算，在原始计数250且方向为下数的翻转边界，会将 `(250+1)%251` 变成0，制造约25μs跳变。最新统计直接一次读取主定时器的count+direction，使用连续的原始相位映射，接受一个tick的估计不确定性。

因此旧报告的极端相位值及超时比例含部分误报，不能当作纯粹的真实中断延误。普通临界区/I2C带来的延误依然存在；分核和预触发均有独立价值。历史日志保留，不覆盖或改写旧数据。

另外，旧TEP方案检查“TEP后25μs”；预触发方案检查“提前触发后37μs”，两者目标都是不跨越下一主PWM TEZ，但不是相同的采样窗口。不能只比较百分比就宣称所有模拟采样问题已经解决。

## 验证范围

“没有跨越下一TEZ”只是采样调度约束，**不等于任意占空比下都落入有效低侧窗口**。真实AB共同窗口仍需依据实际PWM极性、已生效的占空比、驱动死区、运放稳定时间计算，并使用功率波形和电流波形验证。本轮没有把未测的波形或静态零电流误称为已调通的电流闭环。

当前仍是ADC1独占、IDF6.0.2专用底层路径。后续增加WiFi/Flash操作、其他高等级中断或PWM资源使用时，需复核中断抖动、缓存可用性及定时器资源映射；`timer0`假定为本应用第一个MCPWM定时器。
