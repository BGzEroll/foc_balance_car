## 实现

- core0：20kHz同步预触发ADC，M1_AB/M2_AB交替，每相约10kHz，继续整组拒绝失败/超期数据。
- core1：sensor与FOC自由循环，末尾仍调用 `taskYIELD()`，保留原Idle hook。
- 每台电机分别记录有效组序号及上一组代表时间。序号不变则跳过该电机，不重算PI、不改积分、不重复写入其比较器。
- 组代表时间取A/B转换完成时间戳的中点。它是软件时间基准，不等于两相模拟采样孔径同时发生。
- `dt`取当前与上一已见有效组的代表时间差。首次只建立时间基准；后续按真实dt计算。
- 发现零dt或超过1ms的间隔时，本实验跳过该次PI并清积分，记录错误；1ms是实验异常保护值，不是已整定的正式电机保护阈值。
- 两台电机分别调用电流环，并只写对应三个内部比较器。三相安全提交窗口及在TEZ的一致装载仍属于后续工作，本轮没有声称解决。

## Idle hook 是什么

每个核有一个优先级0的Idle任务，执行清理等系统工作；ESP-IDF的任务看门狗也可挂接Idle。Idle hook是Idle任务执行途中调用的应用回调，属于普通任务上下文，不是中断或周期定时器。

当前SDK把 `configIDLE_SHOULD_YIELD` 固定为0。我们的core1应用回调只做计数、`taskYIELD()`，最后返回false，使这次Idle调用不进入等待中断。FOC同为优先级0，因此形成“FOC让出→Idle执行→hook让回→FOC继续”的协作。

看门狗没有注销，也没有在应用hook里替它强行喂狗。这种安排让专用核更忙，不是省电方案；其他更高优先级任务仍可抢占。不能由此推导高优先级常驻FOC任务也能仅靠yield让Idle运行。

依据：[ESP-IDF Idle hook文档](https://docs.espressif.com/projects/esp-idf/en/v5.0.6/esp32s3/api-reference/system/freertos_additions.html)，并已直接核对安装的6.0.2 SDK `freertos_hooks.c` 和 `FreeRTOSConfig.h`。

## 低侧窗口的具体算法：本轮为说明，尚未接入

先明确一种拟采用的极性：上数经过比较值输出LOW，下数经过比较值输出HIGH，PWM低电平对应低侧导通。实际DRV8300模式和波形仍需核实；若极性相反，公式也要相应改变。

在20kHz、50μs周期、峰值250tick、每tick0.1μs时，设某相当前已生效比较值为C，等效高电平占空比为D=C/250（先忽略死区）：

```
低侧开始导通 = 25D μs
低侧结束导通 = 50-25D μs
```

再扣除导通后的死区/驱动延迟/运放稳定时间，以及结束前余量，得到保守稳定窗口。前后余量不必相等，实际值需测定。

示例：假设A相已生效D=40%，B相为60%，为便于计算暂取两端各2μs余量（仅示例，不是已测参数）：

| 相 | 理想低侧导通 | 扣除示例余量后 |
|---|---|---|
| A | 10～40 μs | 12～38 μs |
| B | 15～35 μs | 17～33 μs |

若ADC A约在17～26.5μs读，B约在26.5～37μs读，那么B已越过其稳定区间。虽然37<50，仍不能标为有效低侧采样。

保守实现可以要求整对采样都落在AB共同稳定窗口17～33μs内；该窗口仅16μs，放不下当前约20μs的采集。这是一个简单、充分但偏保守的检查，并非证明物理上绝无可行采样点。

较精细的实现分别判断：A转换区间包含于A稳定窗口，B转换区间包含于B稳定窗口。二者不必全程共同导通。例如上述示意条件下，A若约12～21.5μs、B约21.5～32μs，可能都符合各自窗口；仍需加入真实抖动边界。

“已生效”指当前这个PWM周期硬件真正采用的值。FOC刚提交到影子寄存器、要等下一TEZ才装载的目标值不能拿来判断当前ADC窗口。正式PWM提交逻辑应记录完整三相命令、确定生效周期，并维护对应的已生效版本；当前还没有这层跟踪。
