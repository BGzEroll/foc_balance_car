# 连续运行约 35 分 47 秒后停机的修复

## 实际故障

故障记录：`code=7 motor=1 source=2 age_or_dt_us=1050 adc_age_us=50 heartbeat_age_us=2`。它表示 PWM 提交阶段发现右电机指令所依据的电流样本已超过 1000us，不是过流，也不是 ADC 停采。源编号来自 `motor.cpp` 的 `on_commit`。

停机时上层更新次数为 429496；每次为 5000us，累计 2147480000us，与 2^31=2147483648us 的边界只差 3.648ms。此前被跳过的 FOC 样本使旧指令继续变老，最终在 1050us 时触发保护。

原循环用 `int32_t(sample.timestamp_us - calibration.began_us) < 0` 排除启动前旧样本。连续运行超过 2^31 微秒后，有效新样本也会被这个有符号差值错误拒绝。ADC ISR 和任务心跳仍然运行，因此形成日志里“ADC 很新、心跳很新，但 PWM 指令已过期”的组合。

## 实现

保留 32 位硬件采样戳，但把会话/校准阶段锚点保存为 64 位 esp_timer 时间。获取样本快照后再读当前时间，以无符号的短采样年龄还原 64 位采样时刻，与 64 位阶段起点比较。所有阶段起点写入同步更新两个字段。

纯函数在 `../balance_car/user_lib/hw/sample_time.h`，实际控制循环调用它。该函数只替换启动前样本的判断，原 ADC 新鲜度、1000us 指令有效期、心跳、6A 及其他保护均保留。

## 验证与实际边界

`verify_sample_time.cpp` 编译实际使用的头文件。200282 项检查覆盖启动前样本拒绝、2^31、2^32、多次回绕、一天以上运行时间及随机锚点。简化的 5kHz 样本/提交序列复现旧代码在边界后以 1050us 触发保护；修复后指令样本年龄持续为 50us。

开发机 ESP-IDF 编译通过，USB/IP 原地烧录和回读通过。镜像 SHA256 为 `433a419c35de0e928f8a3795bd6b9c029dc3e514b913d4e65b4d70b40d531582`。正常启动脚本已在停机时成功重载保存参数，随后恢复平衡。

随后 `live_20261024_043520` 连续实机记录运行到主动 STOP，更新次数 478545、约 2392.7s（39分52.7秒），越过原先的 2^31us 故障点。主动停止时 `result=3 fault=0 max_dt_us=5023`，没有再次触发原计时故障。这提供了一次跨故障边界的实物验证，仍不等于任意时长或其他故障条件的耐久保证。

启动期间另外出现过 `fault=9` 校准失败，以及一次短时 `fault=2`。后者停机前编码器年龄约 100～205us、左轮速度升到约 36.37rad/s（底层在 40rad/s 有轮速保护），没有传感器数据断流的明显证据。现有 fault=2 同时用于编码器过期和超速，日志不足以把所有 fault=2 都称为单纯“传感器超时”；它也不应与本次 35 分钟计时故障混为一谈。
