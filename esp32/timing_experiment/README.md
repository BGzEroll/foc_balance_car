# ESP32-S3 电流采样与自由运行 FOC 实测

后续ADC修正及最终固件见[ADC采样修正报告](../adc_experiment/README.md)。本目录保留首轮实验记录，其中相位翻转点误报、同核中断延误与当前板上固件信息均以后续报告为准。

这是板上无功率输出的时序实验，已经实际编译、烧录并采集串口数据。不是电机电流闭环已调通的报告。

## 实际实现

```text
MCPWM 20 kHz，中心对齐，50 μs 一个周期
    TEP / on_full：交替 M1_A→M1_B、M2_A→M2_B
                    写原始码、读数完成时间、序号及采样统计
    TEZ / on_empty：每 20 周期采一次母线，约 1 kHz
                    比较器配置在 TEZ 装载

core1 sensor_foc 任务：非阻塞处理 I2C 完成通知
    → 在临界区取完整 ADC 快照
    → 双电机 Clarke/Park → 电流 PI → 逆变换/共模注入
    → 写入六个内部比较器（三路/电机）
    → taskYIELD()，自由循环

core0：每秒打印一份 JSON 观测记录
```

PI 和扫角采用实际循环间隔 dt，取消固定 1/5000 时间步长。ADC1 运行时仅由 MCPWM 回调使用，FOC 任务不再读取 ADC；母线通道也纳入同一管理。ISR 不计算浮点 FOC。ISR 使用沿用的 ADC LL 单次转换路径，依赖当前芯片及 IDF 6.0.2，不是在 ISR 中调用公共 `adc_oneshot_read()`。

sensor 与 FOC 共用 core1 任务；独立 sensor task 的原 `init()` 入口仍保留，不能同时启动两种模式。I2C 通知位由合并任务读取，ADC ISR 不复用这组任务通知。

## 四组实测

频率由稳定时段两帧之间的计数差/时间差计算。高优先级组包含看门狗诊断干扰，只用于说明失败，不作为可用性能。

| 配置 | 串口采集时长 | 双电机 FOC 循环 | 看门狗 | 说明 |
|---|---:|---:|---|---|
| 任务优先级20，IRQ1，仅任务 yield | 20 s | 约4.83 kHz | 约6 s出现 IDLE1 报警 | Idle 计数停止增长，失败 |
| 任务优先级0，IRQ1，仅任务 yield | 40 s | 约1.00 kHz | 未发现 | 同优先级仍受 Idle 行为限制 |
| 任务优先级0，IRQ1，Idle hook 主动 yield | 25 s | 约3.70 kHz | 未发现 | 可持续调度，但采样相位不合格 |
| 任务优先级0，IRQ3，Idle hook 主动 yield | 45 s | 约3.73 kHz | 未发现 | 最后保留的实验版本；采样相位仍不合格 |

当前 SDK 的 `components/freertos/config/include/freertos/FreeRTOSConfig.h` 明确写着 `configIDLE_SHOULD_YIELD 0`。所以只把任务设为 Idle 同优先级仍不能期待每次 Idle 都立即让回。

应用层注册 core1 Idle hook：计数、`taskYIELD()`、返回 false。返回 false 避免这次 Idle hook 后执行 wait-for-interrupt；不修改 SDK，不注销 Idle 看门狗，也不代替 Idle 手工喂看门狗。这是针对专用 core1 的调度实验，会影响该核空闲等待行为，不能直接作为普适的高优先级实时控制方案。

## 最后候选版的观测

| 指标 | 实测 |
|---|---:|
| 每相真实采样率 | 约9,999.7 Hz |
| 母线采样率 | 约1,000 Hz |
| AB 两路采集阶段，平均/最大 | 18.184 / 18.825 μs |
| A、B 读数完成时间差，平均/最大 | 8.670 / 9.113 μs |
| 双电机数学阶段，平均/最大墙钟时间 | 44.533 / 192.713 μs |
| 包含 sensor、快照、计算和比较器写入的工作阶段，平均/最大 | 225.666 / 1,091.619 μs |
| 自由循环 dt，平均/最大 | 267.633 / 1,180.688 μs |
| M1 / M2 第一相读数完成至开始计算的数据年龄，平均 | 61.063 / 61.747 μs |
| M1 / M2 上述年龄最大值 | 267.619 / 218.344 μs |
| ADC 失败或零码/满量程计数 | 0 |
| 比较器 API 错误计数 | 0 |
| 稳定观测段 Idle hook 执行 | 约4,620 次/s，不代表 CPU 空闲率 |
| 每秒面板观察到的编码器/IMU 最大数据年龄 | 左523、右1,089、IMU5,363 μs |
| 母线校准 ADC 估计电压 | 约8.067 V，并非外部万用表实测 |

墙钟时间包含中断抢占，不是 CPU 净计算时间。数学阶段最小约13.58 μs，平均变大的重要原因是约20 kHz、每次18 μs以上的 ADC ISR 抢占。两相顺序采样，不能把读数完成时间差严格当作模拟采样孔径差。

最后候选版共记录861,822次 TEP 回调，430,911组/电机。FOC 共160,785轮，每轮两电机都获得了新序号，没有重复使用旧序号；大量更早的采样被有意覆盖，只取最新组，不排队补算。FOC运行频率因此不是 ADC 更新频率，更不等于已测得的闭环带宽。

## ADC 时机为何尚不能通过

这里额外统计“驱动回调提供的 TEP 相位估计 + AB 采集耗时是否跨过下一 TEZ”，以25 μs为保守时序诊断界限。

- 最后版本的稳定段约8.88%回调超过这一界限；全程77,354次。将 IRQ 从1升到3没有消除问题。
- TEP 回调间隔观测为21.825～167.213 μs，存在被延后后挤近以及跨周期的情况；`gaps` 为按回调入口时间差估计的227个缺口，不是硬件精确漏触发计数。
- 这项相位估计使用 MCPWM 驱动在回调前读取的计数值与方向，不包含全部入口开销，不能替代逻辑分析仪，更不能单独证明模拟采样窗口有效。
- 25 μs只是 TEP→TEZ 的半周期，不是实际低侧有效窗口；窗口由输出极性、占空比、驱动死区、模拟稳定时间共同决定，可能比它更窄，也可能跨越这个边界。因此这里是“时序基线未达标”，不宣称上述比例等于实际坏电流样本比例。

建议下一步优先定位长临界区、I2C及统计路径对采样入口的阻塞，减少跨核共享锁和ISR内统计；按实际占空比计算AB共同低侧窗口，再安排预触发，使整对采样落在窗口中央。不要简单认为在TEP开始采就已经同步正确。中断优先级提升只能解决可抢占的等待，不能越过屏蔽该等级中断的临界区。

FOC任务继续保持自由运行/yield作为实验路径。若要求严格控制延迟，应重新评估“新数据触发、没有工作时阻塞”的任务组织方式，并明确过载时的执行预算；仅用yield无法保证高优先级任务与Idle共存。

## 尚未验证的内容

本次使用静态电流、测试电角度、测试PI参数与0.2 A内部参考；没有将AS5600角度作为实际换相反馈，没有完成方向、增益、零位或电机参数标定，没有验证真实电流阶跃跟踪。

比较器配置了TEZ装载，但六次比较值写入并非一个硬件原子事务，也没有验证跨TEZ时三相占空比的一致提交和采样→输出固定延迟。功率PWM、DRV8300死区及真实低侧电流窗口均未示波验证。

因此当前可以确认采集和FOC任务路径跑过实板，不能确认真实电机电流闭环已经可用。

## 复查与复现

- `p*_yield*.log`：四组原始串口记录。
- `p*_yield*.json`：每秒JSON帧、捕获时长、固件哈希和故障标记。
- `summary.json`：`analyze.py`计算的计数差结果。
- `prepare.py`：从只读基线生成实验源码，可设 `--priority`、`--irq`、`--no-idle-yield`。默认生成最后候选版。
- `foc_current.cpp/.h`、`sensor.cpp/.h`、`app.cpp`、`test.cpp`：最后实验源码；只适用于已具备本工程其余源码及链接配置的工程，不是独立完整项目。
- `run_hardware.py`：在远端 `build/yield_experiment/` 内运行，会烧录 `build/balance_car.bin` 并复位板子，不能拿来无意中替换正在运行的正式固件。
- `foc_baseline.cpp`、`sensor_baseline.cpp`：本次生成器实际读取的修改前文件。

SDK依据：[FreeRTOS 调度说明](https://docs.espressif.com/projects/esp-idf/en/stable/esp32s3/api-reference/system/freertos_idf.html)、[MCPWM事件及比较器](https://docs.espressif.com/projects/esp-idf/en/v5.1.5/esp32s3/api-reference/peripherals/mcpwm.html)。具体配置同时以本机安装的6.0.2 SDK源码核对。
