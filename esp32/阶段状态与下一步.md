# ESP32阶段状态与下一步

## 当前结论

已经完成ESP32-S3的传感器、ADC同步采集、跨核传递和FOC数学链路的实板验证。现在仍是无功率PWM输出的实验阶段，尚未完成真实电机电流闭环，也没有接入实车平衡控制。

当前最需要补齐的是：完整三相PWM提交与生效周期追踪、按已生效PWM判断低侧采样窗口、明确的启停与超时处理。继续提高自由循环频率不是当前优先项。

## 已经完成

| 项目 | 当前状态 | 边界 |
|---|---|---|
| AS5600、MPU6050 | 异步I²C链路持续更新，实测无停更 | 尚未完成电机方向、电角度零位等换相标定 |
| CPU分工 | core0采ADC，core1合并sensor与FOC | 系统IPC等任务仍存在，不是裸机独占核 |
| PWM时间基准 | 20kHz中心对齐，50μs周期 | 尚未向电机控制引脚输出PWM |
| 采样触发 | 同组备用定时器由主TEZ同步，在TEP前12μs触发 | 提前12μs是当前实验起点，不是任意占空比通用值 |
| 电流轮采 | 每周期采同一电机AB，交替M1/M2，每相约10kHz | AB顺序转换，不是同时采样 |
| 母线采样 | ADC1统一管理，约1kHz | 母线电压来自ADC校准估计，非外部仪表比对结果 |
| 数据传递 | 原子字段加序号锁快照，ISR不等待跨核读者 | 暂未绑定当前生效的PWM版本 |
| 坏组处理 | 转换失败或估计跨下一TEZ时整组拒绝，保留旧值与旧时间戳 | 还没有按实际低侧导通窗口判定 |
| PI更新 | 每电机只使用新有效组，独立dt；无新组就跳过 | 仍为测试角度、0.2A内部参考及测试PI参数 |
| core1调度 | 合并任务优先级5，自由循环、保留yield，已删除Idle hook | 无需保证Idle1获得执行时间 |
| 看门狗 | 关闭Idle1任务看门狗检查，保留Idle0及core1中断看门狗 | 普通控制逻辑卡死不再由Idle1检查覆盖 |

core1当前是一个合并的 `sensor_foc` 应用任务，尚未拆为sensor、FOC两个任务。

## 最后一轮实测依据

测试为60秒串口捕获，53份完整观测；稳定段用于计算频率。不同实验版本的业务负载和统计口径存在差异，不以多轮数字直接推导严格CPU占用率。

| 指标 | 最后实测结果 |
|---|---:|
| 自由任务循环率 | 约8.60kHz |
| M1/M2有效PI更新率 | 约8.126 / 8.119kHz |
| 每相采样尝试率 | 约10kHz |
| ADC无效、比较器API错误 | 均为0 |
| 看门狗、panic、assert | 未发现 |
| 传感器 | 稳定段持续就绪，无停更 |
| 稳定段可用堆 | 固定323,780字节 |
| 估计采样漏周期 | 13 |
| 拒绝组 | M1为43、M2为50，均未发布成新反馈 |

这说明当前分工与数据更新策略可持续运行，不能理解为零抖动、零漏采，也不能把PI调用频率当作实测闭环带宽。

## 尚未完成的关键工作

1. 还没有创建并验证电机引脚PWM波形、DRV8300互补及死区。当前六个控制脚保持输入下拉；这不等于已经证明功率桥处于所有栅极关闭状态。
2. 还没有维护每个周期“真正已经生效”的三相占空比版本。FOC当前分别写比较器，尚未证明三相提交不会跨TEZ混批。
3. 现有ADC检查只约束调度时间，没有根据A/B下桥导通、死区、运放稳定时间确认实际采样有效。
4. FOC没有使用AS5600的标定电角度进行真实换相；实际电流增益、方向、偏置及测量精度仍需校准。
5. PI参数、目标电流、调制限制尚未按电机整定。测试参数不是正式参数，原作者6A限制也没有直接沿用为安全工作值。
6. 正式启停、命令有效期限、反馈过旧/编码器失效处理，以及控制进度监测尚未实现。
7. 尚未做单电机电流阶跃、双电机跟踪与真实平衡外环。

## 推荐推进顺序与验收点

### 1. PWM提交与采样窗口：下一项主任务

先在无功率PWM输出条件下整理数据接口与周期关联：FOC发布完整的单电机三相命令，底层负责在有余量的时段写完，并记录预定及实际生效周期。超过提交截止时间时保留旧的完整输出并记录，不允许部分三相更新。

维护当前PWM周期已生效的比较值，以它计算A/B各自的低侧稳定窗口；保存ADC起止时间，将转换区间与窗口比较。不能拿“下一TEZ才生效的新目标”判断当前采样。

首版可限制调制范围并采用保守共同窗口；随后再考虑逐相窗口、触发点调整及共模安排。窗口不足要明确标记、拒绝或重新安排，不能只要求50μs周期内采完。

验收：命令版本、生效周期、电流组和拒绝原因可追踪；给定软件时序与占空比用例可正确识别窗口内/外；不新增重复积分或跨核ISR等待。这个验收仍不能代替真实PWM波形验证。

### 2. 正式应用入口、启停与故障处理

将测试入口与正式入口分开，建立初始化、校准、READY、RUN、FAULT状态；默认不上电驱动，明确使能与故障清除动作。定义电流、编码器、控制命令过旧以及PWM提交失败的处理。

先根据现有DRV8300接法确认“停机”究竟对应制动、关桥还是电源释放，不能把占空比清零直接命名为关桥。正式运行所需的控制进度/命令超时处理，要独立于已取消的Idle1检查。

验收：上电/复位不会自动使用旧目标运行；无有效数据或故障时不会继续发布新驱动命令。此项完成后再进入实际功率PWM测试。

### 3. 波形、测量与换相标定

在可控、限流条件下验证三路PWM到实际栅极的极性、互补、死区及采样相位。随后校准零电流偏置、增益与方向，确认相序、编码器方向、极对数及电角度零位。

验收：示波波形与软件窗口一致，外部电流测量与反馈量级/方向相符，零电流读数稳定。继续区分电机物理角度与车辆前进方向坐标。

### 4. 单电机小电流闭环

先测一台电机，id_ref先为0，给小幅iq阶跃、正反向与零目标。记录id/iq目标和反馈、母线电压、调制饱和、积分、采样拒绝率及采样到输出延迟，再整定PI及电流限制。

验收：方向正确、响应可解释、无持续振荡，限幅与故障动作有效。不能以“能转”代替电流跟踪验证。

### 5. 双电机、业务负载与平衡外环

先确认双电机独立跟踪和统一的iq_A接口，再加入通信/显示等最终负载做更长时间测试，复核调度、数据年龄及故障处理。最后接速度/平衡外环，按有效IMU数据节拍运行，并与仿真坐标、单位及限流约定对齐。

验收：真实负载下两电机和传感器不互相饿死，出现过期数据时按设计处理，再进入实车平衡调试。
