# 电流接口与作者源码只读核对

核对日期：2026-10-18。只读参考工程 `balance-foc-car-master/BalanceFocCar`，未修改、复制其中的程序文件，也未编译原作者工程。下列内容为独立分析和少量参数记录。

## 结论

仅有PID参数和机械模型，不能唯一反推出电流到力矩的真实比例Kt。缺少同一时刻的实际iq和实际运动响应，或者已知负载转矩。调节Kt并找到一个能站住的仿真，仅能说明该假设与稳定性相容，不能证明它是真实Kt。

当前使用700 KV作为初始假设，沿用独立FOC模型的幅值不变Clarke/Park口径：

```
Ke_phase_peak ≈ 60 / (2π√3 KV)
Kt_iq ≈ 1.5 Ke_phase_peak = 0.011814 Nm/A
轮轴转矩 ≈ Kt_iq × iq
```

这里是FOC的q轴电流，id≈0时与相电流峰值对应；不是电池电流，也不是相电流RMS。商品KV的测量口径、实际反电势波形和损耗未核实，因此不提供虚假的误差百分比。电阻与电感本身不能决定磁链、Kt。7极对也不能独立决定Kt；由KV推算磁链后再乘极对数时，极对数在上述Kt表达式中消去。

参考：SimpleFOC [反电势与KV约定](https://docs.simplefoc.com/voltage_torque_control)，以及项目原先独立FOC模型 `foc_parameters.m`。这里是在同一近似约定下保持模型一致，不是新增测量证据。

| 每台电机目标iq | 暂估转矩 |
|---|---|
| 1 A | 0.0118 Nm |
| 2 A | 0.0236 Nm |
| 6 A | 0.0709 Nm |

已有12°坡中停车记录中，单轮平均转矩约0.01329 Nm，换算约1.12 A；整段单轮峰值0.02272 Nm，换算约1.92 A。这些电流是由已算出的转矩除以假设Kt得到，不是实测电流，更不是反过来验证Kt。运行 `estimate_current_torque_scale` 可重新生成表格与估计JSON。

实机可以利用同样的坡中静止场景做初步辨识：测整车真实质量m、坡角α和有效轮半径r，记录停车时左右实际iq（先统一成向前驱动为正）。忽略额外接触、传动与滚动损耗、左右Kt差异时，沿坡静力平衡给出 `Kt ≈ m*g*r*sin(α)/(iq_left+iq_right)`。当前402.5g、轮半径32.5mm、12°坡约需总转矩0.0267Nm；如果实测两轮电流总和约2.26A，才可由该实测支持Kt约0.0118Nm/A。应在不同坡度和两个方向重复估计，避免把偏置与损耗都当成Kt。现在缺少这个实测电流，不能拿仿真自身生成的电流回代辨识。

## 原作者实际控制链

```
行驶速度误差 → 速度PID → 目标倾角
倾角误差、积分、陀螺仪 → 平衡PID → 电机轮速目标
左右电机各自的速度PI → iq目标 → FOC电流环 → 电机
```

- `lib/SuperCar/SuperCar.cpp:97-100` 同时配置 `foc_current` 转矩层和 `velocity` 运动层。因此调用move时，target仍是机械轮速rad/s，不是A。
- `lib/UserConfig/UserConfig.h:31-32` 电机速度PI的P=0.082、I=2.8；`42-45` 平衡PID的P=1、I=0.08、D=0.02、输出限制100。两者处于不同层，不能拿平衡PID数字直接当电流增益。
- `lib/MPU6050/MPU6050.cpp:155-166` 角速度采用°/s，倾角为°。当前仿真使用rad、rad/s，存在57.3倍单位差异。
- `lib/PID/UprightPID.cpp:51` 平衡积分每次更新直接累加误差×Ki，没有乘实际dt。`VEL_PID_UPDATE=4`、`UPRIGHT_PID_UPDATE=2` 是主循环计数分频，不是4ms和2ms。代码本身不能给出准确更新周期。
- `lib/SuperCar/SuperCar.cpp:128,144` 两台电机配置电流限制6 A。它是控制配置，不能证明电机、驱动器和电池的连续额定能力。
- `lib/SuperCar/SuperCar.cpp:202-203` 两份轮速均读取motor_A，是可疑的反馈取值，未改动原文件。
- 源码中没有Kt或实测磁链，也没有可用于参数辨识的同步电流/运动日志。电流采样电阻0.005Ω、放大倍数50决定采样换算，不决定电机的Nm/A。

具体版本参考：作者platformio声明SimpleFOC ^2.3.3；核对[官方v2.3.3 BLDCMotor.cpp](https://github.com/simplefoc/Arduino-FOC/blob/v2.3.3/src/BLDCMotor.cpp#L428)中velocity模式，速度PI输出current_sp。依赖声明不是该机器已安装版本的证明。

## 当前工程的新选项

面板选择“PID：目标电流输出”，或运行：

```matlab
run_balance_case('recover',true,[],'pid_current');
run_balance_case('drive',true,[],'pid_current',1,'agile');
run_balance_case('slope_hold',true,6,'pid_current',1,'slope');
```

第三个参数对pid_current是单轮iq上限/A，默认6 A；原pid和lqr仍为单轮转矩上限/Nm。新模式的平衡与偏航PID生成左右总电流、差电流，再分配为单轮iq并限幅；机械模型接收的轮轴转矩为 `iq × 标称Kt × 左右执行增益`。电流环暂按理想跟踪，未接入独立FOC的电气动态、母线电压约束、噪声或延迟。

初始化时只将当前已验证的转矩PID的平衡/航向增益除以标称Kt，保持未饱和时的闭环效果；速度PI到倾角的增益不变。这是单位换算，不是套用原作者增益，也不是新增整定效果。Kt与6 A默认值在 `balance_current_parameters.m`。增益主体仍在 `pid_balance_parameters.m`；具体换算后的A制参数保存在每个结果目录的controller_config.json中。

左右执行增益表示实际Kt/标称Kt；测试实际电机更弱时改该增益，不要同时改变用于初始化控制器的标称Kt。若两者同时等比例变化，控制器与对象会相互抵消，无法验证Kt失配。

原始control3d中第22-23列在新模式为A，其他模式仍为Nm；各结果的trajectory.csv始终保留明确的Nm命令列，并为新模式增加 `iq_left_command_A`、`iq_right_command_A`。新模式另输出 `current_torque.png`。6 A按暂估Kt折合0.0709 Nm，比原先0.10 Nm上限低。

`verify_current_interface` 用同一34秒传感序列对比两种单位接口，并检验低电流饱和、左右Kt差异及实际3D的恢复、快速行驶、坡中停车。验证结果保存到 `results/suite/current_interface_checks.json`。

实机若沿用SimpleFOC并让小车PID直接输出iq，运动层应使用torque且转矩层为foc_current；保持velocity模式会把A误当rad/s，还会多出速度PI。这条是实机接口说明，本次没有修改原作者固件。
